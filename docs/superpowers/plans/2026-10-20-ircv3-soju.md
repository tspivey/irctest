# IRCv3 and soju Implementation Plan

**Execution status (2026-10-21):** Tasks 1–9 implemented in the existing `ircv3-soju` worktree. The interrupted all-task draft was preserved and completed as one integration commit, rather than recreating per-task commits. See [verification and review record](../validation/2026-10-21-ircv3-soju.md) for evidence, implementation adjustments, and unperformed live acceptance.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect one saved soju account to its networks automatically, restore conversations quietly, and synchronize explicit read markers while preserving direct IRC behavior.

**Architecture:** Extend the existing Tokio connection tasks and wxDragon tabs. Put capability negotiation, batch classification, bouncer reconciliation, history scheduling, and durable cursor state in independently testable library modules. Keep native display, focus, timers, and speech decisions on the GUI thread.

**Tech Stack:** Rust edition 2024; existing irc-proto, Tokio, chrono, serde/TOML, native-tls, wxDragon, and prismer dependencies.

**Spec:** [Approved specification](../specs/2026-10-20-ircv3-soju-design.md)

## Global Constraints

- Preserve direct IRC connections, existing configuration files, input recall, and unrelated work.
- Keep existing libraries and runtime; no replacement IRC library is required.
- Use the specification's exact capability list, including `draft/chathistory` and `draft/read-marker`.
- Automatic discovery requires configured SASL PLAIN credentials; discovered children authenticate before BIND, then send CAP END.
- Keep IRC callbacks and GUI event handling responsive; use deterministic tests and paused Tokio time instead of timing sleeps.
- Do not replace a running client or connect to an external account without authorization.
- Do not include authentication payloads or password-bearing BOUNCER attributes in display, logs, parse-error diagnostics, or headless traces.
- Retain at most 10,000 output lines per tab.
- Bound negotiation, authentication, and history waits to 30 seconds; role detection has a five-second fallback after welcome.
- Limit simultaneous child registrations to four; history requests to two per connection and one per conversation.
- Default history page size is 100; command count is 1 through 1,000, clamped to the server limit; automatic catch-up is at most 1,000 messages per conversation per connection.
- Initial TARGETS discovery is at most 100 targets; timestamp overlap is five seconds; ID caches hold 4,096 per conversation and persist only the latest 256.
- Bound each connection to 128 active batches, nesting depth 16, and 1,000 buffered messages per history request with a combined four-megabyte text limit.
- Persist versioned metadata in `irctest-state.toml`, using atomic replacement, a single serialized writer, a two-second debounce, and shutdown flush.
- Receiving messages, restoring history, selecting a tab, and queueing speech do not advance read markers.
- Report automated checks separately from live server, keyboard, audible speech, and platform-specific acceptance.

## Review Focus

1. Non-ASCII messages and emoji before the reading cursor: preserve the same selected text and reading position after history insertion; Task 7 pins logical anchors and native conversion.
2. Two accounts with identical network names or IDs: never mix credentials, tabs, logs, or cursors; Tasks 4 and 5 test parent-qualified keys and stable log namespaces.
3. A delayed TLS prompt or network event from an aborted attempt: never change a newer attempt or allow a removed child to restart; Tasks 3 and 4 test attempt envelopes and cancellation.
4. Interleaved nested playback and live CTCP: answer only the live query and preserve current membership; Tasks 2 and 7 test classification through both network and presentation policy.
5. A state write racing with a newer update or application shutdown: retain the newest complete snapshot and never overwrite an invalid file; Task 5 tests serialized writes and flush ordering.

## File Map and Sequence

New library units:

- `src/cap.rs`: capability offers, requests, dependencies, enabled set, registration barrier.
- `src/playback/mod.rs` and `src/playback/batch.rs`: batch ancestry and live/history classification.
- `src/playback/fetch.rs`: bounded history scheduling, selectors, deadlines, and deduplication.
- `src/playback/timeline.rs`: pure line insertion and reading-anchor adjustment.
- `src/bouncer.rs`: parsed network records, snapshots, deltas, and binding metadata.
- `src/connections.rs`: pure child lifecycle and registration queue decisions.
- `src/sync_state.rs`: account/conversation identities, cursor/read metadata, serialized persistence.
- `src/read_marker.rs`: MARKREAD parsing and explicit local/remote marker policy.
- `README.md`: supported capabilities, configuration, commands, and limitations.

Modify the existing network, formatting, routing, configuration, logging,
commands, and GUI files only where their current responsibilities require it.
Add module exports to `src/lib.rs` with each owning task. Keep tests beside the
implementation, extending the existing network duplex harness. Tasks depend on
the preceding public interfaces; execute in order. No scaffolding-only task.
