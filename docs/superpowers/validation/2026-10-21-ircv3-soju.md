## Delivered behavior

The approved nine-task plan is implemented: general capability negotiation and
server echoes; historical batch isolation; authenticated automatic soju network
discovery and binding; bounded child lifecycles and stale-attempt rejection;
durable received cursors and separate read state; bounded history scheduling,
TARGETS discovery and overlap deduplication; quiet insertion with native reading
anchors; explicit `/markread` and unread labels; and user documentation.

All event consumers, including the headless example, compile with the new event
and request interfaces. Existing direct IRC, configuration defaults, input recall,
certificate decisions and rejoin behavior remain covered by the tests.

This implements the supported subset in the approved specification. It does not
implement every IRCv3/soju extension; exclusions are listed in README.md.

## Independent review

An independent reviewer examined the core modules and final GUI integration.
The reported important findings were corrected and covered by tests:

1. Tagged/prefixed raw credential commands bypassed feedback redaction.
2. An oversized physical historical line could produce an untagged live tail.
3. Equal timestamps prevented older history from advancing opaque message IDs.
4. Manual soju bindings with network/client username selectors could be duplicated.
5. History timeout/failure and marker acknowledgement/failure could miss a renamed query.

The final independent review reported no remaining Critical or Important findings.
No minor findings were deferred.

## Execution decisions and interface adjustments

The original execution ledger decisions, in order, were:

1. Continue in `/tmp/irctest-ircv3-soju` instead of master so the original checkout
   remains available. Cost: integration is a separate local step.
2. Preserve the uncommitted broad draft and the separately verified predecessor
   worktree; harden the existing feature draft instead of rebuilding completed
   work. Cost: a larger integration diff. A snapshot was saved at
   `/tmp/irctest-resume-draft-backup.tar.gz` before resuming edits.
3. Consolidate the interrupted all-task draft into one integration commit rather
   than fabricate earlier task-by-task commit boundaries. Cost: a larger commit
   for review.
4. Label history without a valid source time as `[unknown date]` and keep it out
   of date-based catch-up logs. Cost: undated historical content is display-only.

Additional implementation details resolve interfaces without changing the goal:

- Single-parameter CAP requests use irc-proto's valid serialization without the
  optional colon. Draft capability names remain unchanged.
- `BatchMeta` includes parent/history/exhaustion metadata, and raw batch-type
  recovery avoids irc-proto's uppercasing of opaque custom batch types.
- History completion includes `pending`, distinct from archive exhaustion, so
  continuing catch-up pages keep their insertion boundary.
- Canonical length-delimited conversation identities are TOML string keys;
  serialized metadata contains no message bodies or passwords.
- Native output uses logical unwrapped lines and native XY position conversion
  with the tested timeline helper. Actual platform accessibility acceptance is
  still separate from those pure tests.
- The original protocol behavior that cut oversized input into separate parsed
  chunks was replaced with bounded physical-line discard, preventing history
  and credential-bearing tails from becoming ordinary live messages.
